# 结构化摘要

## 先确认对象与用途

- 对象：文件 / 目录 / 仓库 / 网页 / 一段对话
- 用途：快速了解？决策依据？转述给别人？决定摘要的详略与角度。

## 采集素材

```bash
# 仓库：先看结构与入口
ls -la
cat README.md 2>/dev/null
find . -maxdepth 2 -name "package.json" -o -name "pyproject.toml" -o -name "go.mod" | head
```

单文件超过 500 行时，用 grep 抓标题/函数签名，再分段读重点部分，不要一次性读完浪费上下文。

## 输出模板（按需裁剪）

```
## 一句话结论
<这个东西是什么 / 回答了什么问题>

## 关键要点
1. ...
2. ...
3. ...

## 结构 / 流程
- A → B → C

## 需要注意的点
- 风险、未决问题、与预期不符之处

## 延伸
- 想深入了解可以看：<文件:行号 / 章节>
```

## 规则

- 忠于原文，不补充原文没有的信息；推断的内容必须显式标注「推测」。
- 保留关键数字、路径、命令、专有名词，不要泛化成「一些配置」。
- 长文摘要控制在原文的 5%~15%；代码仓库摘要控制在 400 字以内加一份目录树。
- 如果素材不足以支撑结论，直接说缺什么，而不是硬编。
